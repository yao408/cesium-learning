项目经历
灾害应急可视化平台 个人项目 · 全栈开发
面向地震灾害应急的三维态势感知系统，覆盖地震监测、空间分析与应急调度全流程。前端采用毛玻璃清透风格，绿色为主色调，面板半透明叠层与三维场景形成视觉层次。
前端：Vue 3 · Pinia · Vue Router · Cesium.js · Vite   后端：Spring Boot · JPA · PostgreSQL   工具：OSRM路径规划 · Docker · Nginx
  • 三维场景与图层管理：基于 Cesium 构建三维 GIS 可视化系统，加载全球地形影像，实现震中定位、脉冲标记与相机飞行。设计多图层管理架构，支持震中、监测站、救援车辆、边界等 7 类图层独立显隐
  • 渲染优化：使用 DOM 叠加层替代 Cesium 原生 Billboard 渲染监测站图标，避免三维地形场景下的纹理模糊与裂纹，图标随地球旋转始终锚定地理坐标，hover 弹出站点详情
  • 通视分析：基于地形采样沿 360° 射线逐点计算遮挡关系，精确定位可视终点与遮挡点坐标；同时支持 GPU ShadowMap 面着色模式，快速呈现整体可视域，为瞭望塔选址提供决策依据
  • 洪水扩散模拟：基于 WebGL 着色器实现 GPU 并行水流扩散，模拟水沿地形自然流动；结合 Marching Squares 算法实时提取淹没边界多边形，边界与地形紧密贴合，可直接导出 GeoJSON
  • 救援路径规划与模拟：集成 OSRM 路径规划，自动生成周边城市至震中的救援路线；支持动态增删救援车辆、手动编辑路径点，车辆沿路径自动行驶，支持播放控制、速度调节与相机锁定跟随
  • 后端数据服务：基于 Spring Boot + JPA + PostgreSQL 搭建 RESTful API，实现监测站、车辆、瞭望塔等实体的 CRUD 接口，支持坐标范围查询与属性筛选，前后端通过 axios 联调，数据持久化存储
  • 性能探究：对比 entities 与 PointPrimitiveCollection 两种渲染方式，1000 个点 entities 降至 5 FPS，Primitive 稳在 60 FPS，理解 GPU 批量渲染在大规模场景中的必要性

后端开发
灾害应急后端服务 Spring Boot + PostgreSQL
技术栈：Spring Boot · Spring Data JPA · PostgreSQL · RESTful API · Docker · Nginx
  • RESTful API 设计：实现 8 个 CRUD 接口，涵盖监测站（/api/stations）、车辆（/api/vehicles）、瞭望塔（/api/watchtowers）、震中（/api/epicenters）等实体，遵循 REST 规范（GET/POST/PUT/DELETE），统一 JSON 响应格式
  • 数据持久化：使用 JPA 实体映射 + PostgreSQL 存储，支持经纬度范围查询（BETWEEN）、属性筛选、分页排序；利用 @Transactional 保证数据一致性
  • 前后端联调：Vite proxy 代理解决开发跨域，axios 拦截器统一处理请求/响应，实现数据接入模块与三维场景联动，后端不可用时前端自动降级使用本地 mock 数据
  • 部署方案：前端 npm run build 生成 dist，Nginx 反向代理 /api 转发后端；Docker Compose 一键启动前后端 + 数据库，了解 CI/CD 流程
